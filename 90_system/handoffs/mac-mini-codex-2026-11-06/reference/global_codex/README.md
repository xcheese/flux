# 全局 Codex 规则维护

维护源是本目录；生效副本位于 `$CODEX_HOME`（未设置时为 `~/.codex`）。日常业务任务不运行全局同步；维护任务由 Codex 按已有授权处理。

## 同步入口

需要 Python 3.11 或更新版本，只使用标准库。入口依次检查 PATH 和常见 Homebrew Python 位置，跳过不兼容版本；也可通过 `CODEX_SYNC_PYTHON` 指定现有解释器，指定值无效时明确报错。脚本不联网、不安装软件、不修改全局环境、不启动模型任务。

```bash
bash sync.sh --check
bash sync.sh --apply
bash sync.sh --rollback <备份编号>
```

不带参数等同 `--check`，只检查不写入。退出码：0 为成功或已一致，2 为存在待同步差异，1 为冲突或错误。输出为 JSON 摘要，不输出完整配置内容。

管理范围：全局 `AGENTS.md`，以及 coding-guardrails、diagnosing-bugs、code-review、tdd、long-goal-execution 五个完整技能目录。同步脚本、说明和测试留在维护源，不复制进技能目录。

默认 `--check` / `--apply` / 当前批次的 `--rollback` 仅管理规则与上述技能：不读取、解析或改写 `config.toml`，不要求任何审批配置或第三方技能目录存在。历史配置跟踪保留，避免丢失将来显式迁移时的冲突依据。

旧配置迁移仅在显式添加 `--migrate-config` 时执行：将已经启用的自动审批兼容名称规范为 `auto_review`，移除 `features.js_repl`，禁用指定 20 个重复入口。这是单独授权的配置操作，不能用于只有文本同步授权的任务。`--check --migrate-config` 可先只读审阅；回退涉及配置修改的旧批次也必须显式携带该参数。保留 `.agents/skills` 中的版本，禁用路径为 `.claude/skills/<名称>/SKILL.md`；共享文件和 `.codex/skills` 链接不删除。名单在 `sync.py` 的 `DUPLICATES` 中。

模型、推理档位、项目、插件、MCP、通知及其他权限设置不归该工具管理。显式迁移首次禁用重复入口前要求两份资源一致；保留入口缺失或已被禁用时拒绝继续。完成去重后，第三方更新可由保留目录承接，不要求两份永久一致。

## 备份与冲突处理

首次应用以前，核对完整差异并确认维护源已吸收生效版本中的约定。首次应用建立已同步状态；之后比对该状态，检测目标文件的后续编辑。

私有备份在 `$CODEX_HOME/backups/global_codex/sync-*`，同步状态为 `$CODEX_HOME/global_codex_sync_state.json`。备份目录权限为 0700，备份文件为 0600；不要将备份或完整 `config.toml` 提交进知识库。应用有变化时才生成新备份；重复应用没有新差异时不写文件。

遇到受管文件分叉，先核对用户的后续修改并合并到维护源，再同步；源和目标已一致时可更新同步基线。无强制覆盖开关。受管目录中额外出现的未知文件须先检查，不能默认删除。普通 TOML 排版采用局部编辑，并对比完整解析结果；无法安全识别的写法会在写入前报错，不重写整份配置。

回退只还原该批实际修改的文件和配置项，保留其他后续配置变化。同一受管内容已被再次修改时先报冲突；存在后续同步批次时，按最新批次先回退。写入中断时自动尝试回退已写部分，无法安全回退时报告备份编号，保留后续编辑供检查。

硬中断后可能留下 `prepared` 批次。`--check` 会报告未完成批次，不把文件内容碰巧一致当作同步完成；下一次 `--apply` 会先按最新批次顺序尝试受保护回退，再重新应用。若有用户后续编辑则停止覆盖。写入前会核对所有受管文件和目录类型及目标路径，避免无效源文件导致部分写入。

## 有限验证

```bash
"${CODEX_SYNC_PYTHON:-/usr/local/opt/python@3.14/bin/python3}" -B -m unittest discover -s tests -v
```

上面的解释器路径是本机已确认安装位置；其他机器指定自己的 Python 3.11+。测试使用临时目录，覆盖原有迁移、内容同步的配置字节保留、解释器选择、只读检查、幂等应用、完整资源同步、后续编辑保护、中断恢复及回退。`--target-root` 和 `--user-root` 可指定隔离目录，不需要修改全局环境。

应用后再通过实际桌面/终端运行时的 `skills/list` 检查启用入口和错误。技能正文按官方校验器检查；同步工具不会启动模型对话来测量自动触发率。

修改 `config.toml` 后，官方要求重启 Codex。新启动的检查进程读取新配置，不代表已打开的桌面会话也已刷新；在运行中的任务结束后重启应用，再使用新的会话清单核对。技能正文自动检测与配置重新加载是两件事。依据：[官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

三个社区适配技能保留各自的上游提交与许可证。升级时比较并合入有用差异，保留本地自动选择、授权复用和项目验收边界。CLI 升级另行执行，不由同步脚本自动拉取。

## 本地领域技能适配

`skill-adaptations/2026-11-06.json` 记录八个视频/演示技能入口及五个按需参考文件的目标路径、修改前后哈希与可得的上游来源；同名 `.patch` 保存本轮完整差异。适配已写入记录所指的本地技能目录，没有修改插件缓存或已禁用的 `.claude` 副本。这些领域文件不属于默认 sync 的五个工程技能目录。

第三方更新前先比较安装文件与记录的修改后哈希。若不同，先审阅新版本，再合并仍适用的本地触发边界与授权复用规则；不要盲目重放补丁。拆出的说明仍与入口位于同一目录，保留原有相对资源路径。原始文件的私有备份路径记录在 JSON 中；新增文件回退时需先核对当前哈希，仅删除本批新增且未被后续修改的文件。
