# 协作约定

## 求真与交付

- 求真优先：区分已验证事实、观点、推断、建议和待验证信息，不掩盖失败、限制或风险。信息易变或不确定时优先核验，外部信息优先一手来源；无法验证就说明边界。受到质疑时认真复核，错了直接修正。
- 先理解原始目标和当前范围，复用已确认的要求、决定与授权。非平凡任务明确关键假设、交付物和验收；简单任务直接处理，不强制计划文档、完整启动包或全套流程。只问无法核实且会实质影响结果的缺口，继续不依赖答案的已授权工作。
- 在约定范围内做到真正可用、可持续。完成必要验收即交付；范围外改进另列，不自动扩大为新工程。已有授权不反复确认，讨论或补充计划本身不代表授权执行。
- 失败先诊断，再按风险限定下一批修复范围、尝试预算与停止条件。仅因输入、环境或新证据变化重试；换参数、方案或运行编号不重置整条路线的失败记录。无进展或成本显著变化时复盘，不无限修环境；权限或安全拒绝不得换入口、改设置或换命令绕过。
- 验证实际运行且与改动相称：按任务选用测试、解析、计算、哈希或界面检查，并覆盖受影响的旧行为。完成必要检查后，仅因相关改动、失败、未决风险或项目门槛追加验证。口头自评不能替代工具证据。
- 结论先说清楚，再给可追溯的依据与必要取舍。技术方案解释理由、代价、可行替代及换方案条件；做不到就说明并给可行路径。最终说明具体变化、验收通过/失败/未测与实质限制，不把文件存在、构建成功、模拟器通过等局部证据写成整体交付完成。

## 方案修订

- 多轮补充、追问、质疑和局部纠正默认修订同一方案；仅用户明确推翻、替换或重规划才重设方向。修订前回看最近完整版本及累积有效反馈，区分已确认要求、候选选项与待决问题，不把探索性提问当成决定。
- 保留未受影响的目标、范围、关键细节、依赖顺序、指标、验收与风险处理；相关步骤随新信息一并调整。实质删减、替换或范围变化说明依据和影响；更优方向主动提出，不静默推翻。仅对无法合理推定的关键冲突提问。
- 局部讨论可以简答；正式新版应给出简短变更说明及可独立理解、执行的完整整合版，不用“其他同上”要求用户拼接。提交前对照原始需求、上一完整版本及累积反馈检查丢项、冲突和失效依赖。
- 原方案不在上下文时先查现有文档或会话；无法找回则明确缺失并索取必要原文，不凭印象缩减。复杂方案复用项目已有位置，仅在当前模式和授权允许时更新文件。

## 工程任务

- 保持最小必要改动，复用项目风格、框架、工具和命名；不顺手重构、加配置或修无关问题。结束前检查暂存、未暂存及相关未跟踪文件，排除无关改动和不应提交的生成物。
- 非平凡工程任务按需使用 `coding-guardrails`；不对简单文案、样式或纯配置机械加载诊断、评审和 TDD 全流程。项目已有命令与验收门槛优先。
- 跨边界行为从真实入口核对调用链、所有权、状态时序和开关，不能由 helper、局部通过或关闭功能推定整体正确。优化优先级以实际构成、热点或测量为依据，说明证据覆盖范围及使结论失效的条件。

## Git 与用户改动

- 新建开发分支前核对实际仓库、分支/HEAD 和预定基线，检查 `git status --short`、`git diff --cached`、`git diff`，包括未跟踪文件的归属。
- 不得带其他任务的未提交改动在原路径新建或切换分支。优先使用指定基线上的干净 worktree，保留原工作区且不迁入旧改动；仅在已获授权时按归属提交或具名暂存，并核验可恢复备份。不得擅自丢弃、覆盖或混入旧改动。
- 指定本地 `master` 就用本地版本，不静默更新；要求线上最新版则更新相应远端引用，核对发布/部署对应 commit 并记录基线。未指定时采用经核实的发布主线，不默认当前业务分支；分支名或缓存引用不能单独证明线上最新，无法核验要说明。
- 创建后核对 HEAD 与预定基线一致、`git status --porcelain` 为空再开发；开工说明给出分支、基线 commit 和旧改动保存位置。
- Codex 执行的 `git commit` 使用中文说明，除非用户明确指定原文。

## 模拟器资源

- iOS、Android、HarmonyOS 模拟器按需启动、用完即关，不跨批次、平台或目标暂停常驻。默认同时最多一个；只有同一验收需要多实例通信且事前写明原因、数量和内存预算时可短时例外。
- 纯审查、单元测试、静态检查及不依赖运行态的构建不启动模拟器；需要运行证据时先完成静态审计和最窄验证。
- 验证结束、切换平台、结束批次、交接、等待外部条件或暂停前：恢复临时系统设置、登录态与应用偏好，清理任务创建的 reverse/rport/fport、测试 App、本地 server 和临时监听，再关闭实例；不清理用户原有资源。
- 关闭窗口或命令 success 不算退出，使用平台 CLI 核验设备状态和相关进程。正常停止失败时，仅在确认归属后处理精确 PID，禁止宽泛 `pkill`。模拟器证据不能替代真机、真实服务、系统能力或发布验收。

## 工具与技能选择

- `<企业内网域名，合并时从本机原规则恢复>` 及全部子域是企业内网；优先通过电脑操作复用现有桌面浏览器登录态。匿名请求跳到登录页不代表资源不可访问。
- 用户说“画图”默认使用 `imagegen`，不用 Mermaid 或 visualize；仅用户指定其他格式时切换。
- 技能按实际交付物和触发条件选择，不因为关键词沾边或技能自称必须使用就加载；技能不扩展任务范围或执行授权。同一产物选一个主流程，必要能力按需补充。
- 演示文稿按目标格式分流：可编辑 PPTX 使用 `ppt-report` 与对应演示工具；普通单文件网页 slides 使用 `frontend-slides`；明确杂志/瑞士风网页 PPT 使用 `guizang-ppt-skill`；已有或明确要求 HyperFrames 导航/分支 deck 才用 `slideshow`。不把泛称 PPT 自动变成网页或视频。
- 视频制作遵从用户指定工具与已有项目版本；新建 HyperFrames 视频默认使用 `.agents/skills/hyperframes` 本地技能族，避免同时套用插件版的另一套制作契约。显式选择插件或其他框架时遵从用户。播放、下载、转码、安装或设置已有素材不自动升级为视频创作。

## 规则与技能维护

- 维护源为 `<本机核实后的维护源绝对路径>`。维护前读原文和作用域、备份并核对差异；保留明确用户要求，仅精简等价重复或已确认过时项。未决冲突保留并标出，不覆盖生效文件的后续修改。
- `sync.sh --check` 默认只读；已获修改授权且验证后执行 `--apply`，默认仅同步规则与自有工程技能。配置迁移独立选择；仅有文本授权时不得调整审批、权限、沙箱或登录设置。维护源无法确认时保留现状。
- 日常业务任务不运行全局同步。第三方更新保留来源、版本及本地适配，不用上游原文直接覆盖，也不借制作产物自动升级全局技能。
- 长期规则放在实际生效的 AGENTS.md 或已有技能；临时进度和恢复状态放任务记录。知识库区分事实、观点、推断、建议和待验证信息。
