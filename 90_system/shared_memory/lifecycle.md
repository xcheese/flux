# Shared Memory Lifecycle v1

## 1. 写入规则

- 只有能让未来 ChatGPT / Codex 少问一次、少重复一次判断、少踩一个坑的信息，才值得写入。
- 临时信息默认进入 `episodic`。
- 不确定信息必须标 `draft` 或低 confidence。
- 不要把未经验证的推断写成事实。
- 不写入密钥、token、私人证件、敏感账号。
- 不写入未授权大段版权内容。
- 不把临时路径当长期事实。

## 2. 晋升规则

- `episodic` 多次复用或多次被验证后，才能晋升到 `internalized`。
- 可复用 SOP、判断框架、长期工作法，可晋升到 `growth`。
- `core_identity` 必须非常克制，只有长期稳定规则才能进入。
- 晋升时必须保留来源路径或说明依据。

## 3. 衰减规则

- 一次性任务、过期计划、旧版本路径，应从 `indexes/current.md` 移除。
- 旧规则被新规则替代时，旧条目标记为 `superseded`，不要直接删除。
- 错误记忆标记为 `deprecated`，并说明原因。
- 不再活跃但仍有历史价值的条目标记为 `archived`。

## 4. 冲突规则

新旧记忆冲突时，不要静默覆盖。创建新的 `decision` 记录，说明：

- 旧规则是什么。
- 新规则是什么。
- 为什么替换。
- 影响哪些路径或流程。
- 回滚条件是什么。

## 5. 安全规则

- 不保存密钥、token、登录态、账号密码、证件号码。
- 不保存未授权整本书、完整付费课程、大段版权文本。
- 外部事实要有来源路径；无法验证时标为待验证。
- 用户偏好和长期规则需要保留来源或最后确认时间。

## 6. `current.md` 规则

`indexes/current.md` 只放当前最重要、最高频、最需要快速读取的信息：

- 当前活跃项目。
- 当前重点目标。
- 关键系统路径。
- 最新重要产物。
- 最近 3-5 条有效变化。
- 下一步动作。

不要把历史流水账塞进 `current.md`。
